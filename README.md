# Farhood Agentify

المرحلة الأولية لإدارة المطاعم والاشتراكات. الواجهة تدعم تسجيل دخول Supabase للمشرف وعرض المطاعم وإضافتها، وإضافة الباقات وتسجيل الاشتراكات أو إلغائها في قاعدة البيانات. لا تنشئ الإضافة موقعاً أو حساب عميل أو اشتراكاً تلقائياً. بقية الأقسام قيد التطوير.

## التشغيل

```bash
npm install
cp .env.example .env.local
# ضع رابط المشروع والمفتاح العام publishable في .env.local
npm run dev
```

استخدم المفتاح العام فقط في متغيرات `NEXT_PUBLIC_`؛ لا تضع مفتاح service role أو أي مفتاح سري في الواجهة أو المستودع. عند النشر اضبط المتغيرات نفسها في Cloudflare وأعد البناء. يجب اختبار توافق إصدار Next.js وطريقة النشر المختارة.

## Supabase والصلاحيات

تم تطبيق مخطط `supabase/migrations/20261108000100_foundation.sql` على مشروع Farhood-Agentify المرتبط. يتضمن المطاعم والعضويات والباقات والمميزات والاستثناءات والاشتراكات وطلبات الدفع، مع تفعيل RLS. حساب المشرف لا يُمنح تلقائياً: يجب إنشاء حساب Supabase Auth ثم تعيينه من جهة موثوقة في جدول `platform_admins`. لا توجد صفحة تسجيل عام في التطبيق. يجب اختبار RLS بحسابات مختلفة قبل الإنتاج.

قائمة المطاعم وملخص الاشتراكات يُقرآن من Supabase؛ الحالة المعروضة تستنتج من تاريخ الانتهاء وفترة السماح المسجلة، وليست آلية لوقف الموقع. إدارة الاشتراكات أولية: لا توجد بعد آلية تجديد متكاملة أو حفظ للسعر وقت الاشتراك، أو تذكير وإيقاف المواقع، أو استقبال طلبات دفع من العملاء، أو الثيمات. توجد واجهة أولية للمشرف لتسجيل الدفعات يدوياً ومراجعتها والمصاريف؛ التقارير تعرض مجموع الدفعات المؤكدة مطروحاً منها المصاريف لكل عملة على حدة لجميع الفترات، ولا تتحقق من التحويلات أو تفعّل الاشتراك. هذه ليست محاسبة مكتملة. مدة الاشتراك تحسب بإضافة شهر أو سنة مع تقريب نهاية الشهر، حسب الوقت المحلي للمشرف عند الإدخال. الاشتراك السابق المسجل بحالة فعّالة يجب إلغاؤه يدوياً قبل تسجيل بديل. لم تُدرج أسعار افتراضية لأنها لم تُعتمد. لم يُختبر تسجيل الدخول والإضافة والمراجعة من طرف لطرف عبر المتصفح بعد.

تم تطبيق `supabase/migrations/20261108000200_platform_expenses.sql` لإضافة مصاريف المنصة مع سياسة تتيحها للمشرف فقط. بيانات الدفع والمصاريف يجب مراجعتها بعناية، ولا توجد حالياً آلية كشف تكرار التحويلات أو ربط دفعة باشتراك أو استرجاعها.

يمكن للمشرف تسجيل المميزات وتعيينها للباقات أو إضافة استثناءات لكل مطعم من قسم الباقات. هذه إعدادات بيانات فقط: لا تُطبّق المميزات على مواقع المطاعم أو تمنع الوصول إليها بعد، ويلزم تنفيذ تحقق آمن من الاشتراك والاستثناءات عند بناء كل ميزة.

## Cloudflare Workers (الواجهة الحالية)

المشروع الحالي يُصدّر كملفات ثابتة (`out`) وتُنشر عبر Workers Static Assets باستخدام `wrangler.jsonc`. إعدادات Git builds: أمر البناء `npm run build`، أمر النشر `npx wrangler deploy`، وأمر معاينة الفروع `npx wrangler versions upload`. اضبط متغيري `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` كمتغيرات بناء؛ يُضمّنان في الواجهة عند البناء ويجب إعادة البناء بعد تغييرهما. لا تستخدم مفتاح service role. إعداد static export مناسب للوضع الحالي فقط؛ أي وظيفة Next.js تحتاج خادماً تتطلب تعديل طريقة النشر. النشر يتطلب رفع الفرع وتحديده في إعدادات البناء على Cloudflare.
